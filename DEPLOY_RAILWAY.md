# Pear CM: постоянный запуск через Railway

Railway запускает бота как постоянный Docker worker. Конфигурация находится в `railway.json`; сборка использует существующий `Dockerfile`, а политика перезапуска — `ALWAYS`.

## Первичная настройка

1. Войдите в Railway и создайте новый проект из GitHub-репозитория `awesome371828/botiris`.
2. Выберите ветку `main`. Railway должен обнаружить `railway.json` и собрать Dockerfile.
3. В настройках сервиса добавьте переменные окружения:
   - `TELEGRAM_BOT_TOKEN` — токен из BotFather.
   - `SUPABASE_URL` — URL проекта Supabase.
   - `SUPABASE_SERVICE_KEY` — service-role key Supabase.
   - `BOT_OWNER_ID` — Telegram ID владельца Pear CM (если не задан, код использует значение по умолчанию).
4. Запустите деплой и проверьте логи. Убедитесь, что в логах есть сообщение о запуске polling и нет `TelegramConflictError`.
5. Проверьте команды бота в Telegram.
6. **Только после того, как Railway успешно запустил бота и он отвечает**, откройте GitHub → Actions → workflow `Run Pear CM` → меню `…` → Disable workflow. CI-проверки оставьте включёнными. Это предотвращает запуск второй копии с тем же токеном.
7. Убедитесь, что никакой другой VPS/хостинг/локальный компьютер не запускает этот же токен.

## Важно

- Не отправляйте токен бота и ключ Supabase в чат и не коммитьте их в репозиторий.
- Для постоянной работы выберите в Railway тариф/план, который поддерживает постоянно работающие сервисы и не засыпает worker.
- Автоматический перезапуск помогает восстановиться после завершения процесса, но не исправляет ошибку приложения, неверный токен, ограничения Telegram или сбой самого провайдера.
- GitHub Actions runners временные и не предназначены для гарантированного непрерывного polling 24/7.
